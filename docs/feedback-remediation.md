# 用户反馈修复方案与优先级

基线为 2026-11-17 核对的 main `eed3e0c`。本轮以源码、固定输入解析及本地 Chromium 复现为依据，目标是保留用户原步骤和业务预期，提高可执行性诊断和证据可信度。业务系统的复杂表单、窗口滚动和原始生成文件尚未复验，不计作已确认修复。

## 实施顺序

| 顺序 | 优先级 | 事项                                                                      | 修复范围及验收重点                                                                                                        |
| ---- | ------ | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 1    | P1     | [步骤与断言证据 #26](https://github.com/anthonyli/laya-pilot/issues/26)   | 普通 Excel 每个逻辑步骤及预期结束时留图，失败保留现场；JSON、CSV、Markdown 关联原文、范围、时间与真实文件，兼容最终截图。 |
| 2    | P1     | [先审用例流程 #27](https://github.com/anthonyli/laya-pilot/issues/27)     | 先在 skill 分流中明确审核约束，避免误用会实际操作的 generate；再设计独立草稿入口、已确认计划版本和执行约束。              |
| 3    | P1     | [用例可执行性诊断 #25](https://github.com/anthonyli/laya-pilot/issues/25) | inspect 和报告区分缺少测试值、未支持动作和缺少业务判定依据；后续受约束地编译明确断言，保留原文映射与未验证项。            |
| 4    | P2     | [无标签图标诊断 #28](https://github.com/anthonyli/laya-pilot/issues/28)   | 保留未识别控件证据，逐级解析可核实标签；缺少语义或无法唯一定位时不猜测动作。                                              |

P1 优先修复影响用户理解、操作边界和结果复核的问题；P2 扩展控件发现能力。表中顺序是可独立交付的实现顺序，不代表低序号事项覆盖率更高。每项 issue 包含复现、方案、验收和验证边界，合并各项修复后再更新实际完成状态。

截图在步骤或断言结束时采集，不能承诺捕获此前消失的瞬时提示；结构化生成/回放的逐步截图不在此次范围。控件诊断对应各用例结束时快照。显式绑定仅支持普通 Excel 主页面，审核计划执行不接受额外绑定覆盖目标。

## 实现边界

- #25 不通过改写测试目标来提高通过率。“数据与条件一致”需要明确数据来源和判定规则，不能降级为“筛选控件存在”；缺少输入值时也不能替用户猜值。
- #27 保留当前验证式生成入口。草稿必须标为未验证，不能把 `--inspect` 当作草稿生成，也不能将只读操作等同于完全不操作页面。
- #28 优先使用当前页面可核实语义，不把位置、图标形状或 CSS 类名直接当作导出、删除等业务动作。
