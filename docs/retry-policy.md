# 生成与回放的三次尝试策略

适用范围：生成模式，以及 `--excel` 自动识别的结构化执行计划（兼容旧 `--mode execute`）中的工作流步骤。

- 每个逻辑步骤最多尝试三次，包含首次执行。成功立即继续；嵌套定位、断言等辅助函数共享预算，不叠加成九次。
- 定位、填写、断言等失败后重新观察或定位。生成时，创建入口优先换用尚未尝试的匹配入口；没有其他入口时可重试原入口。
- 保存、删除、确认先检查可操作性。一旦尝试发送点击，后两次仅等待请求并核查结果，避免重复写入。不能确认成功时仍报告失败。
- 三次均失败，终止当前用例的剩余步骤，记录失败步骤、各次原因和截图，继续后续独立用例。新增或修改失败时，依赖其记录状态的用例标记为依赖阻断。
- 截图在清理弹窗前保存；在途写请求未结束时不强行关闭弹窗。清理失败不会使其他独立用例从报告中消失。
- 不降低模型决策阈值，不强制点击被遮挡的控件，不要求模型在信息不足时猜测。重试成功也不会覆盖用例内已观察到的严重浏览器或接口错误。

结果文件：`results.json` 包含每条用例的 `attempts`；`报告.md` 展示逐次尝试；回放 Excel 的备注包含尝试记录。失败截图保存在 `evidence/`。

真实后台端到端验证仍需针对目标应用执行；单元测试不代表所有页面结构均已兼容。
