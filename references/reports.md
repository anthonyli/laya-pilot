# 测试报告怎么看

每轮执行生成一个独立目录，默认在执行命令时所在目录的 `runs/laya-pilot/<日期_时间>/`，如 `runs/laya-pilot/2026-11-20_13-47-22/`。用 `--out DIR` 可指定位置。`runs/laya-pilot/latest.json` 记录最近一轮的位置和结论。

普通 Excel、结构化用例、生成用例和录制回放都使用同一套目录结构，整个目录一起发送即可，所有链接都是相对路径。

## 目录结构

```text
runs/laya-pilot/2026-11-20_13-47-22/
  index.html          从这里开始：可靠性结论、用例列表、每一步的截图
  summary.md          文字版报告，适合直接阅读或交给 AI
  results.json        机器可读的完整结果
  results.xlsx        每条用例一行；第二张表是每个步骤和预期（Excel 类执行）
  cases/              每条用例一个目录
    001-标题检查/
      01-步骤1-已完成.png
      02-预期1-通过.png
      final.png       用例结束时的页面
      controls.json   用例结束时识别到的控件
    002-缺失内容/
      03-预期2-失败.png
      trace.zip       这条用例的执行轨迹（只有未通过的用例才有）
  run/                整轮级别的截图：启动或登录失败、运行中断
  playwright-report/  录制回放时 Playwright 自带的 HTML 报告
  logs/               过程文件，排查问题时再看
```

截图文件名依次是：顺序号、这一步做了什么、结果，例如 `03-预期2-失败.png`、`03-点击-保存-通过.png`。看文件夹列表就能找到失败的那一步。普通 Excel 和结构化用例（生成与回放）每一步都有截图；重试的步骤带“第 N 次”。

**执行轨迹按用例保存。** 每条用例单独录制轨迹，记录每次点击、页面变化和接口请求。用例通过就删除轨迹，失败、阻断、未验证或被中断时保留在该用例目录，目录不会因为通过的用例变大。登录过程不录制。

## 先看 index.html

在执行测试的目录运行 `fa report` 打开最新报告，包括通过 `--out` 保存到其他目录的报告。用 `fa report RUN_DIR` 打开指定一轮，也可直接双击 `index.html`。Skill 入口使用 `node scripts/run.mjs report [RUN_DIR]`。

页面最上方是**可靠性结论**，回答“这轮结果能不能信”：

| 结论             | 含义                                                         |
| ---------------- | ------------------------------------------------------------ |
| 通过，证据完整   | 全部用例通过，没有阻断、未验证预期、页面或接口错误，截图齐全 |
| 通过，但需要复核 | 没有失败，但存在下面列出的问题，通过不能直接说明业务正确     |
| 未通过           | 有用例失败、运行没有正常完成，或存在未确认的写操作           |

结论下方逐条列出原因，常见的有：

- **阻断或未执行完**：前置条件、登录或前序用例出问题，这些用例没有真正验证页面功能。
- **预期未验证**：预期写得无法自动判定，需要补充可观察的结果，或人工确认。
- **页面、脚本或接口错误**：执行中出现可见错误提示、脚本异常、HTTP 错误，或接口返回 `success: false`。
- **截图没有采集成功**：证据不完整，需要结合轨迹复核。
- **读取用例时有警告**、**本轮只执行了部分用例**：覆盖范围比 Excel 少。
- **本轮没有调用模型**：结果来自固定规则和断言，没有验证模型决策接口。

用例列表中，失败、阻断和未验证的用例排在前面并自动展开，按时间顺序显示每个步骤和预期的状态与截图。点击缩略图可在报告内放大，按 Esc、点击遮罩或关闭按钮即可回到原步骤。展开“检查与诊断”可查看该用例的详细记录。

## 定位一个失败

1. 在 `index.html` 找到标红的用例，看原因和失败那一步的截图。
2. 打开该用例的 `cases/<编号>-<名称>/` 目录，按顺序号对照前后几步的页面。
3. 需要看点击、请求和页面变化的过程时，打开该用例目录里的轨迹：`npx playwright show-trace cases/<编号>-<名称>/trace.zip`，或把文件拖到 <https://trace.playwright.dev>（文件只在本机浏览器中解析）。保存失败时，`index.html` 和 `results.json` 的 `trace_error` 会说明原因，不会留下打不开的文件。
4. 怀疑用例解析或选择范围有问题时，再看 `logs/`。

## logs/ 里的文件

| 文件                          | 内容                                                     |
| ----------------------------- | -------------------------------------------------------- |
| `excel-inspection.json`       | Excel 的解析结果、诊断，以及每条预期如何拆成断言         |
| `selection.json`              | Excel 读取多少条、本轮执行多少条                         |
| `decisions.ndjson`            | 每次模型决策的输入摘要与结果                             |
| `browser-events.ndjson`       | 各用例期间的浏览器错误和接口事件（结构化用例）           |
| `startup-browser-events.json` | 进入用例前的浏览器事件                                   |
| `progress.ndjson`             | 执行进度事件                                             |
| `checkpoint.json`             | 已完成用例、当前步骤与未确认写入（结构化用例），原子写入 |
| `review-plan-approval.json`   | 审核执行时批准的草稿摘要                                 |
| `trace-error.json`            | 结束运行时轨迹保存超时或失败的原因                       |

`--inspect` 只检查用例文件，产物只有 `logs/excel-inspection.json` 和 `logs/selection.json`。

## 注意

- 截图是采集当下的页面，不代替断言，也可能错过两次采集之间短暂出现的提示。
- `results.json` 中如有 `pendingWrite` 或 `retainedRecord`，先核对 `logs/checkpoint.json` 和截图，不要直接重跑写操作。
- 原始工作簿始终不会被改写；结构化用例和生成用例的结果写在 `results.xlsx`。
